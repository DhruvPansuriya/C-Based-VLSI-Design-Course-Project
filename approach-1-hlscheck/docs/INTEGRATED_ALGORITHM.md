# HLSCheck: certified relational summaries and counterexample refinement

The default checker now implements one verification procedure. Custom symbolic
execution/Z3 produces proof obligations and summaries that change the C product
program verified by ESBMC/Z3. It does not select one verifier's independent
whole-program answer after another verifier fails.

This is our implementation of a combination of established compositional
verification, translation validation and abstraction/refinement ideas. It is
not a claim that those ideas, or this entire combination, are new research.
ESBMC's source code is unchanged and remains an attributed upstream component.

## One command and one contract

```powershell
.\.venv\Scripts\python.exe -m hlscheck original.c candidate.c --function kernel --output-dir results/my_check
```

The public Python API is `hlscheck.verify_equivalence`. The older
`check_equivalence` API and explicit `--backend symbolic|esbmc|auto` commands
remain available to reproduce historical experiments and perform ablations.
The default command uses the combined algorithm.

A shared frontend preprocesses modelled `stdint.h` types and source macros,
resolves integer typedefs, checks C syntax/types and records one contract.
The integer target is ILP32: char8, short16, int32, long32 and long-long64;
plain char is signed. ABI assertions enforce the expected widths. Original
primitive integer rank and qualifiers are preserved. No 64-bit input is
generated by narrowing a 32-bit nondeterministic value.

The current default limit is 60 seconds per SMT check/C-verifier invocation.
Frontend work and expression construction add wall time. The original
10-second results and source snapshots remain separate from the larger
instance study in `results/large/REPORT.md`. Source-location/time macros,
floating-point constants, string storage, array rebinding and address-taking
are outside the admitted integer/value model and are rejected.

The observation is the return value and every final parameter-array element.
Arrays must be valid and nonoverlapping. Both programs must be safe on the
admitted domain for an equivalence proof. Explicit scalar preconditions are
recorded; incomplete loop unwinding is inconclusive, never a proof over an
unstated smaller input domain.

## Proof construction

1. **Choose a relational state boundary.** A leading region can contain
   declarations and fixed-loop nests. No local variable may escape the region
   into the suffix, and no scalar parameter may be modified. The two regions
   may have different loop nests. If no suitable prefix boundary exists, a
   function-exit boundary can include all array outputs and the return value.
2. **Prove the region relation.** Our symbolic executor expands supported
   loops and builds bit-vector expressions. Z3 checks region safety and
   equality for all admitted input states. Polynomial normalization and
   separately discharged component lemmas remain available. Only an
   `equivalent` result licenses region abstraction.
3. **Build one residual C product.** Replace the proved region pair by shared
   arbitrary array poststates. For a complete function-exit summary, the return
   poststate is shared as well. ESBMC verifies the two remaining computations,
   retaining bounds, pointer, signed-overflow, division, shift, uninitialized
   and unwinding checks.
4. **Refine abstract counterexamples.** Shared arbitrary poststates can lose
   correlations, such as `out[i] = 13*a[i]`. A mismatch or safety violation in
   that coarse model is not automatically real. Generate an exact functional
   summary from the symbolic source expressions, independently prove the
   generated C summary equivalent to the source region, and recheck the
   residual C with the restored correlations. If the summary cannot be
   generated or certified, restore the original region in the same product.
5. **Validate full-exit SMT counterexamples.** A complete-function symbolic
   mismatch proposes a concrete input. ESBMC checks the actual unabstracted C
   pair at that input. A confirmed mismatch is a refutation. Agreement at that
   one input cannot establish equivalence: discard the proposal and verify
   the full input domain instead.
6. **Return one verdict and its dependencies.** The result identifies the
   common contract, region lemmas, summary-encoding lemmas, refinement history,
   residual C proof and available concrete input. Accepted SMT queries are
   exported and replayable; raw C-engine traces and hashes are retained.

If no region relation can be proved, the initial residual is the original C
product. This is the opaque-region case of the same procedure. No unsupported
construct is silently approximated, and no unknown result is called equivalent.

## Why shared poststates are sound

Let `P0` and `P1` be the two prefixes, and `S0` and `S1` their suffixes. The
region obligation proves, for every initial state `I`, that both prefixes are
safe and have equal observable cut states:

```text
state(P0(I)) = state(P1(I))
```

All real pairs of prefix poststates are therefore contained in the larger set
of arbitrary equal poststates. Proving suffix equality and safety for that
larger set proves them for real prefix executions. The boundary checks ensure
that no relevant scalar/local state was omitted.

The converse does not hold: a counterexample in the larger set can be
unreachable. Exact-summary refinement restores the source-state relationship.
The summary emitter is not trusted on its own: a second SMT obligation must
establish that its generated C has the source region's semantics.

A differing intermediate region is also not necessarily a differing program.
Later code may overwrite its outputs. Such a failed region lemma is recorded,
and the unabstracted computation remains in the C verification problem.

## Example requiring cooperation

The demonstration computes a fixed matrix product, then reads a result through
a symbolic index. Our standalone symbolic checker can prove the loop algebra
but cannot model the symbolic read. A monolithic C verification has to compare
different nonlinear loop implementations. The combined algorithm proves the
matrix-region relation, shares its poststate and verifies the indexed read in
the residual C.

```powershell
.\.venv\Scripts\python.exe -m hlscheck benchmarks/hybrid/gemm_lookup_original.c benchmarks/hybrid/gemm_lookup_optimized.c --function gemm_lookup --output-dir results/gemm_demo
```

Another example compares `return out[index]` with `return 13*a[index]` after
equivalent loops. A coarse shared-state abstraction loses that correlation and
initially fails. A certified exact summary restores it and the proof succeeds.
Changing the second return to `13*a[index]+1` still produces a real mismatch
after refinement.

## Evaluation and evidence

`scripts/run_hybrid_study.py --ablation` evaluates the new procedure separately from
the historical 50-pair, local-model, subtle-control and public-leaf studies.
Its results are under `results/hybrid/`. The three mixed examples compare
standalone symbolic checking, monolithic C checking and the combined method.
These are targeted examples, not a random benchmark sample or a statistical
speedup experiment. Limits are per obligation; the combined procedure may
issue several obligations, so equal total budgets are not claimed.

Tests cover spurious abstract counterexamples, incorrect generated summaries,
local live-outs, intermediate mismatches later overwritten, incomplete
unwinding, false witness proposals, 64-bit high inputs and signed boundaries.
Concrete mismatch inputs are independently executed in the actual C pair when
the trace supplies a complete vector. Abstract poststates are never used as
native-program inputs.

## Current limits and attribution

This first implementation extracts one leading region or one function-exit
region. It does not infer arbitrary cutpoints, loop invariants or relational
summaries for all C constructs. General pointers, heap allocation, function
calls, globals, aggregate state, volatile/atomic behavior and general floating
point remain outside the shared frontend. The custom summary engine still
uses unsigned-32 data; broader integer types can remain opaque in the C product.

Residual verification can dominate runtime, including safety checks and trace
generation. The method is not guaranteed to be faster than monolithic checking,
and inconclusive results are retained.

ESBMC supplies C symbolic execution and bounded verification; Z3 supplies SMT
reasoning. Our contributions are the region relation, boundary checks, shared
state abstraction, certified summary generation, refinement rules, product
construction, typed integration and experiment/evidence infrastructure. See
[the ESBMC usage documentation](https://esbmc.github.io/docs/usage/) for the
upstream verification and witness facilities. The project also retains the
APLAS 2017, PAST/FPGA 2024, Alive2 and PEQcheck references discussed in the report.
